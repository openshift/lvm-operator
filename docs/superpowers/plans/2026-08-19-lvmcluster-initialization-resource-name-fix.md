# LVMCluster Initialization-Resource Name Fix Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the OpenShift Console show the same default `LVMCluster` name (`my-lvmcluster`) regardless of which "Create instance" entry point the user takes, fixing [OCPBUGS-86002](https://redhat.atlassian.net/browse/OCPBUGS-86002).

**Architecture:** The CSV carries two independent OLM annotations that each embed a sample `LVMCluster` CR: `alm-examples` (generated from `config/samples/lvm_v1alpha1_lvmcluster.yaml`, name `my-lvmcluster`) and `operatorframework.io/initialization-resource` (hand-written JSON literal in the CSV base, name `test-lvmcluster`). This plan renames only the `metadata.name` field inside the `initialization-resource` JSON literal so both annotations agree, then regenerates the derived bundle/catalog manifests.

**Tech Stack:** YAML manifest editing, `make bundle`, `make catalog`, `make verify` (no Go code changes).

## Global Constraints

- Rename only `metadata.name` inside the `initialization-resource` annotation — do not add `default`/`fstype`/`overprovisionRatio`/`sizePercent` or otherwise change its `spec` fields (per spec: those differences are intentionally out of scope).
- Do not hand-edit `bundle/manifests/lvms-operator.clusterserviceversion.yaml` or files under `catalog/` — they are generated by `make bundle` / `make catalog` and must only be produced by running those targets (per `AGENTS.md`: never edit generated files, and any CSV-affecting change requires `make bundle && make catalog`).
- Do not modify `config/samples/lvm_v1alpha1_lvmcluster.yaml`.
- Commits must be signed off (`git commit -s`) per `CONTRIBUTING.md`, and any AI-generated commit needs a `Co-Authored-By:` trailer.
